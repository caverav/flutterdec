# Pipeline phase baseline: A/A noise floor at 1371e42

Two independent A/A runs of the phase harness, measured before any product
change, to establish what the ruler reports when nothing has changed. Both sides
of both runs are the same product revision, so every non-zero delta below is
measurement error by construction.

Everything here is reproducible from the artifacts in `docs/baseline/`. The
harness patch is committed alongside its digest; applying it to a worktree at
`1371e42` reconstructs both binaries.

## 4. Schedule and pair order

Three one-time unmeasured warmup passes per binary, run once before any measured
pair. Zero warmups inside every measured pair. Fifteen interleaved pairs.

Execution order alternates inside the pair: reference first on even pair
indexes, candidate first on odd ones. The order that actually executed is
appended by the measuring function itself, not by the loop, and is recorded per
run in `docs/baseline/aa-*/pair-order.tsv`. The harness restates the schedule
independently after the loop and diffs it against that log; both runs printed
`pair order verified alternating across 15 pairs`.

Fifteen is odd, so the split is 8 pairs reference-first and 7 pairs
candidate-first. That residual one-pair imbalance is inherent to the
contract-mandated 15 pairs and is quantified in section 6.

## 5. Correctness

The correctness pass runs once per binary in the warmup invocation and covers
all 33 disclosed cases: block count, successors, dense ids, predecessor
reciprocity, non-empty artifact, function declaration, no dangling helper call,
and emission determinism.

All four binaries: 33 of 33 cases passed, `correctness_failures` empty. See
`docs/baseline/aa-*/warmup-{reference,candidate}.json`.

### Position effect

Measured directly rather than assumed. Within one binary, comparing its
first-position pairs against its second-position pairs on the combined span:

| Run | Side | (second - first) / first | MAD | cases |
| --- | --- | --- | --- | --- |
| aa-1 | reference | -0.00209 | 0.00401 | 33 |
| aa-1 | candidate | -0.00092 | 0.00432 | 33 |
| aa-2 | reference | -0.00206 | 0.00371 | 33 |
| aa-2 | candidate | -0.00173 | 0.00362 | 33 |

Second position is about 0.2 percent faster, consistently and for both sides.
With 8 pairs one way and 7 the other, the residual that survives alternation is
roughly one fifteenth of that, about 0.01 percent, which is negligible against a
noise MAD of 1 to 2 percent.

### Residual asymmetry, and what it is not

Sign balance is not centred. Of 165 cells, aa-1 reports 116 candidate-slower and
aa-2 reports 109. Restricting to cells whose absolute delta reaches 2 percent:
aa-1 has 22 such cells, 11 each way; aa-2 has 28, of which 20 are
candidate-slower.

This is not the position effect. Holding position fixed and comparing the two
binaries only against each other in the same slot, the asymmetry survives at
full strength:

| Run | Phase | candidate vs reference, both first | both second |
| --- | --- | --- | --- |
| aa-1 | emission_exclusive | +0.01104 | +0.01165 |
| aa-1 | combined | +0.00699 | +0.00581 |
| aa-2 | emission_exclusive | +0.01632 | +0.01851 |
| aa-2 | combined | +0.00997 | +0.01116 |

The cause is the binaries, not the schedule. The worktree path enters the crate
metadata hash, so two builds of one source revision at two paths are not the
same machine code. Demonstrated directly:

- Same source at `pathtest/reference`, built, then its target directory deleted
  and rebuilt at the same path: byte-identical, sha256 `42e92daa321e7f59...`,
  1869920 bytes. The build is deterministic at a fixed path.
- Same source at `pathtest/candidate`: sha256 `75303789a789d37f...`,
  1869984 bytes. Different code for identical input.

So the harness carries a build-layout floor of roughly 1 to 2 percent on
`emission_exclusive` and about 1 percent on `combined`, in a direction fixed by
which path each side happens to occupy. It reproduces across both independent
runs, so it is a bias rather than noise, and averaging more pairs will not
remove it.

It stays well inside the 5 percent MDE floor and no cell clears its MDE, but it
is stated here rather than left to the floor to absorb: a real product change
worth less than about 2 percent on the emission span cannot be separated from
which worktree it was built in. Section 7 records the fix.

## 7. Limits

- Build-layout bias, above. The fix is to make the two builds path-independent,
  for example `--remap-path-prefix` on both worktrees, or building both sides at
  one fixed path in sequence. Neither is applied here: the change belongs to a
  harness revision, and applying it would invalidate the two baselines in this
  document.
- Fifteen pairs is odd, so the alternating schedule cannot split positions
  evenly. Residual position exposure is one pair in fifteen.
- The `cfg` span shares an allocation counter with emission and is not reported
  separately, because reading the counter inside the CFG span is the one place
  the instrumentation deliberately does not reach.
- Both runs are single-host and single-session. Nothing here characterises
  cross-machine variance.
- These are A/A runs against the disclosed matrix only. The held-out matrix is
  not exercised, and by contract its seed is drawn after the candidate commit.

## 8. Invalidated run

Recorded numbers from the invalidated run, kept for comparison only:

a baseline.

## 9. Reproducing

```
git worktree add --detach <TREE> 1371e42
git -C <TREE> apply --whitespace=nowarn docs/baseline/harness-b4b1d8c.patch
```

then the section 2 command. The harness refuses to reuse an output directory
that already holds raw samples, holds an exclusive lock for the whole run, and
exits non-zero if the two sides' workload manifests differ or if the executed
pair order is not the alternating schedule.
