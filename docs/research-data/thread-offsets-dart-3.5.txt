#
# Counts are IR instruction counts, from every direct load or store off x26 in
# the disassembly of one sample binary. LocalSend for 3.5 (snapshot hash
# 80a49c7111088100a233b2ae788e1f48), Immich for 3.12
# (ace654289f5abc240509fc941453ebc5). They are not emitted-line counts.
#
# Classification: a name ending _entry_point_offset or _stub_offset, and the
# write_barrier_wrappers entries, are function pointers. Everything else is a
# data field.
#
# NOT YET USED, and the reason is the gate. The same displacement means
# different things across versions: 0x68 is field_table_values on 3.5 and end on
# 3.12; 0x238 is a stack-overflow stub on 3.5 and the slow allocation stub on
# 3.12. 110 of 111 common offsets moved between these two versions, and only 3
# agree between the compressed and uncompressed blocks of a single version. So
# naming requires an exact match on both the snapshot hash and the pointer mode,
# and anything else has to keep the numeric thread.fN form.
#
# Four offsets per version are DERIVED rather than exported: object_sentinel,
# empty_array, empty_type_arguments and dynamic_type are declared contiguously
# by CACHED_NON_VM_STUB_LIST in runtime/vm/thread.h and have no generated AOT
# constant, so their offsets follow from object_null plus a word each. Treat
# them as derived from the declaration order, not as table constants.
